ReciMate error and loading states

Read-only snapshot for spec 009. The loading, error and no-results states of the Library (including the failure modes of search) and of Details, in the current look: native toolbar, one Filters button, no chips. The error is the system ContentUnavailableView with one message for every error and a Try Again button; loading is the system ProgressView. Both sit in an overlay over the screen's content, so the title, search field and Filters button never move. The system draws the toolbar, search field and error view differently on iOS 26 (glass), so the SwiftUI will not match pixel for pixel and should not be rebuilt to. Static: nothing animates. Changes from the spec 003 frames: no custom badge circle, no "Back to Recipes" button, no Clear Filters button, no chips, one generic message instead of per-recipe wording. The empty collection frame (003, frame 5) is not drawn: it is outside the brief and lives in the backlog.
